JDU Portfolio Workspace — сценарий презентации для отчётного совещания

Демонстрационный URL:
https://jdu-signal-archive.ishonchsavdo1.chatgpt.site

Рекомендуемый формат: 8–10 слайдов, 5–7 минут.
Визуальный стиль: тёмная SaaS-панель, фиксированный sidebar, крупные карточки 4:3, фиолетово-розовые и оранжевые акценты, короткие тезисы на слайдах. Интерфейс и демонстрация показывают рабочие состояния профиля, проектов и Board.

Слайд 1. Название проекта
Заголовок: JDU Portfolio Workspace
Подзаголовок: Многоязычный онлайн-архив студенческих проектов JDU
На слайде: имя студента, группа, дата, ссылка на demo.
Комментарий докладчика: «Проект создан в рамках пересдачи Cowork. Его задача — собрать студенческие проекты в едином визуальном пространстве».

Слайд 2. Проблема
• Проекты находятся в разных папках, презентациях и ссылках.
• Посетителю сложно быстро понять цель проекта и найти demo.
• Студенту не хватает единого места для вопросов и обратной связи.
Комментарий докладчика: «Я решил превратить разрозненные материалы в каталог с понятной карточкой проекта».

Слайд 3. Концепция решения
• Каталог проектов JDU.
• Поиск, категории и фильтры Draft/Published.
• Карточка проекта с Overview, Questions и Board.
• Отзывы и оценки сообщества.
• Интерфейс EN/RU/UZ/JP.

Слайд 4. Визуальное направление
Показать скриншот главного экрана.
Тезисы: dark premium UI, fixed sidebar, rounded navigation, hero-блок, карточки 4:3, акцентные градиенты.
Комментарий докладчика: «Визуальная система повторяет эстетику Design Rocket, но контент и логика адаптированы под учебный архив JDU».

Слайд 5. Пользовательский сценарий
1. Пользователь открывает Library.
2. Выбирает категорию или статус.
3. Находит карточку через Search.
4. Открывает Project drawer.
5. Переходит в Overview, Questions или Board.
6. Оставляет вопрос или отзыв.
7. Автор открывает профиль, добавляет проект как Draft или Published, редактирует его и перемещает задачи по Board.

Слайд 6. Живая демонстрация
Порядок показа:
1. Открыть demo URL.
2. Переключить язык.
3. Выполнить поиск и применить фильтр.
4. Открыть проект Nihongo Talk Trainer или Osh Table.
5. Показать Questions и Board.
6. Добавить демонстрационный вопрос или отзыв.
7. Открыть Profile, сохранить профиль и показать выбранный Track.
8. Открыть Add project, создать Draft-карточку, затем показать Edit project, Publish и Board.
Примечание: вопросы, отзывы, оценки и цифры на demo являются sample data и не являются реальной статистикой.

Слайд 7. Техническая реализация
• Frontend: React + TypeScript + Vinext.
• UI: CSS с адаптивной вёрсткой.
• Backend: Vinext API route handlers.
• Database: Cloudflare D1; таблицы profiles, projects, questions, reviews и board_items.
• Storage: Cloudflare R2 для аватара профиля и обложек проектов.
• Deployment: Cloudflare Sites.
• Identity: workspace-authenticated user headers для изменяющих операций; владелец может изменять только свои проекты и Board.

Слайд 9. Результаты и ограничения MVP
Результаты:
• Рабочий многоязычный frontend.
• Подключённый D1 backend с сохранением профиля, проектов, вопросов, отзывов и Board.
• R2-хранилище для медиа и владельческие проверки изменяющих операций.
• Подготовленные документы и тестовый отчёт.
Ограничения:
• Нет отдельной панели модерации.
• Production demo имеет private owner-only доступ до отдельного решения о доступе преподавателя.
